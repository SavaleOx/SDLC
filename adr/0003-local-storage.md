# ADR-0003: Локальное сохранение в SQLite через QSQLITE

* **Статус:** Принято
* **Дата:** 2026-10-25
* **Автор:** Савонов А.И.
* **Связанные требования:** `REQ-FUNC-010`, `REQ-FUNC-011`, `REQ-REL-001`, `REQ-REL-002`, `REQ-SEC-001`

## Контекст и постановка задачи
Приложение должно локально сохранять привычки и статусы по датам между запусками, обеспечивать восстановление данных после перезапуска и контролируемо обрабатывать ошибки чтения/записи. Данные имеют табличную структуру: привычки с параметрами типа, единиц измерения и повторения, а также статусы по датам. Необходимо выбрать формат хранения, не раздувая зависимости проекта.

## Рассмотренные варианты
1. **SQLite через Qt SQL и драйвер QSQLITE (файл `habits.db`)**
2. **Сохранение в JSON/INI-файл с ручным парсингом**
3. **Бинарная сериализация собственной структуры**

## Принятое решение
Выбран вариант **1: локальная база SQLite `habits.db` через Qt SQL и драйвер QSQLITE**.

### Обоснование
* **Табличная структура данных:** привычки и статусы по датам естественно ложатся на две таблицы (`habits` и `statuses`) со связью по `habit_id`; выборки для календарной таблицы и статистики выполняются SQL-запросами без ручного разбора файла.
* **Целостность и восстановление (`REQ-REL-001`, `REQ-REL-002`):** SQLite обеспечивает атомарность транзакций; при ошибке чтения/записи приложение не сообщает об успешной операции (`REQ-SEC-001`), а факт ошибки доступен для диагностики.
* **Штатная поддержка в Qt:** драйвер QSQLITE входит в поставку Qt SQL, отдельная СУБД и сервер не требуются; файл `habits.db` хранится локально.

## Последствия
* **Положительные:** единая схема данных для таблицы привычек и статистики, воспроизводимое восстановление данных после перезапуска (`REQ-FUNC-011`), отсутствие серверной части.
* **Отрицательные:** требуется корректная обработка ошибок открытия и SQL-запросов; при изменении схемы необходимо предусматривать миграцию или проверку версии схемы при открытии БД.
