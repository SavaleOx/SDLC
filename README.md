# Идеальный день

Утилита на **Qt (C++)** для анализа распорядка дня. Пользователь вводит время подъёма, сна, работы и отдыха — программа оценивает день по шкале от **0 до 100**, формирует вердикт, указывает проблемные места, даёт советы и строит альтернативное **«расписание для счастья»**.

## ✨ Возможности

- 📝 Ввод расписания дня через диалог с `QTimeEdit`.
- ✅ Валидация данных с понятными сообщениями об ошибках.
- 📊 Оценка дня (0–100) по категориям: **сон**, **работа**, **отдых**, **баланс**.
- 💬 Текстовый вердикт с эмодзи и указанием слабого места.
- ⚠️ Список замечаний и персональных рекомендаций.
- 🌈 Генерация расписания «для счастья» на основе введённых данных.
- 🌙 Тёмная тема оформления.
- 🔄 При повторном открытии диалог восстанавливает последние значения.

---

## 🔧 Как это работает

1. Пользователь нажимает **«Ввести данные»**.
2. Открывается `InputDialog` с текущим расписанием (или значениями по умолчанию).
3. После подтверждения данные передаются в `DayModel::setSchedule()`.
4. Модель валидирует расписание, рассчитывает оценку, формирует вердикт, замечания, советы и строит идеальное расписание.
5. Модель испускает сигналы `scheduleChanged` и `analysisChanged`.
6. `MainWindow` обновляет интерфейс автоматически.

## 🏗 Архитектура

Проект построен по паттерну **MVC** (Model–View–Controller) с использованием сигналов и слотов Qt.

```
┌────────────┐   inputRequested   ┌──────────────────┐
│ MainWindow │ ─────────────────► │  DayController   │
│  (View)    │                    │                  │
│            │ ◄───────────────── │  открывает       │
│            │  scheduleChanged   │  InputDialog     │
│            │  analysisChanged   │                  │
└────────────┘                    └────────┬─────────┘
                                           │ setSchedule()
                                           ▼
                                    ┌──────────────┐
                                    │   DayModel   │
                                    │   (Model)    │
                                    └──────────────┘
```

- **View** (`MainWindow`) — отображает данные, emit-ит `inputRequested`, не знает о модели.
- **Controller** (`DayController`) — связывает View и Model, открывает диалог ввода.
- **Model** (`DayModel`) — хранит расписание, выполняет валидацию, анализ и построение идеального расписания.

## 🚀 Сборка и запуск

### Требования

- **Qt 5.15+** или **Qt 6.x** (модули `Core`, `Gui`, `Widgets`).
- Компилятор с поддержкой **C++17**.
- `qmake` или `CMake`.

### Сборка через qmake

```bash
qmake project.pro
make          # или mingw32-make / nmake на Windows
./ideal_day
```

### Пример `.pro`-файла

```pro
QT += core gui widgets
CONFIG += c++17
TARGET = ideal_day
TEMPLATE = app

SOURCES += \
    main.cpp \
    mainwindow.cpp \
    daycontroller.cpp \
    daymodel.cpp \
    inputdialog.cpp

HEADERS += \
    mainwindow.h \
    daycontroller.h \
    daymodel.h \
    dayschedule.h \
    dayanalysis.h \
    inputdialog.h \
    intervalutils.h
```

### Сборка через CMake

```cmake
cmake_minimum_required(VERSION 3.16)
project(ideal_day LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_AUTOMOC ON)

find_package(Qt6 REQUIRED COMPONENTS Widgets)

add_executable(ideal_day
    main.cpp
    mainwindow.cpp
    daycontroller.cpp
    daymodel.cpp
    inputdialog.cpp
)

target_link_libraries(ideal_day PRIVATE Qt6::Widgets)
```

## 📦 Формат данных

### `DaySchedule`

```cpp
struct DaySchedule {
    QTime wakeUp;      // подъём
    QTime sleep;       // отход ко сну
    QTime workStart;   // начало работы
    QTime workEnd;     // конец работы
    QTime restStart;   // начало отдыха
    QTime restEnd;     // конец отдыха
};
```

> Интервалы могут пересекать полночь (например, сон с 23:00 до 07:00). Утилиты в `intervalutils.h` корректно обрабатывают такие случаи.

### `DayAnalysis`

```cpp
struct DayAnalysis {
    bool valid = false;
    double score = 0.0;         // 0..100
    QString verdict;            // текстовый вердикт
    QStringList problems;       // замечания
    QStringList advice;         // рекомендации
    DaySchedule idealSchedule;  // «расписание для счастья»
};
```

## 📊 Система оценивания

Максимальная оценка — **100 баллов**:

| Категория | Макс. балл | Что учитывается |
|-----------|-----------|-----------------|
| **Сон** | 35 | Длительность (7–9 ч), время отхода (около 23:00), качество (не днём, не слишком поздно/рано). |
| **Работа** | 25 | Длительность (6–8 ч оптимум), отсутствие ночных часов (00:00–06:00). |
| **Отдых** | 20 | Длительность (1.5–3 ч оптимум), удалённость от работы и сна. |
| **Баланс** | 20 | Доля сна, соотношение работа/отдых (2:1–4:1), наличие свободного времени. |

**Дополнительные штрафы:**

- сон < 5 ч → **−5**
- отдых > 5 ч → **−3**
- отход ко сну между 06:00 и 10:00 → **−2**

Итог ограничивается диапазоном `[0, 100]`.

### Вердикт

| Баллы | Вердикт | Эмодзи |
|-------|---------|--------|
| ≥ 90 | Отличный день! | 💚 |
| ≥ 75 | Хороший день. | 💛 |
| ≥ 55 | Средний день. | 🧡 |
| ≥ 35 | Слабый день. | ❤️ |
| < 35 | Очень плохой день. | 💔 |

Дополнительно указывается **«слабое место»** — категория с наименьшим отношением набранных баллов к максимуму.

## ✅ Валидация

**Быстрые проверки в `InputDialog`:**

- начало и конец работы не совпадают;
- начало и конец отдыха не совпадают.

**Проверки в `DayModel::validateSchedule`:**

- все поля заполнены корректным временем;
- сон: **4–12 ч**;
- работа: не 0 и не более **16 ч**;
- отдых: не 0 и не более **16 ч**;
- работа и отдых не пересекаются;
- работа не пересекается со сном;
- отдых не пересекается со сном.

> При ошибке валидации анализ помечается как `valid = false`, а пользователю показывается предупреждение.

## 🌈 Построение идеального расписания

Алгоритм `DayModel::buildIdealSchedule()`:

1. **Якоря сохраняются**: время подъёма и начала работы берутся из пользовательского расписания.
2. **Сон**: ровно **8 часов** назад от подъёма.
3. **Работа**: если длительность > 8.5 ч — обрезается до **8.5 ч**.
4. **Отдых** (по приоритетам):
   - если пользовательский отдых ≥ 2 ч и не пересекается с работой/сном — оставляем как есть;
   - иначе пробуем растянуть его до 2 ч, сохранив начало;
   - иначе ищем лучшее свободное окно — либо после работы, либо после подъёма, с отступом 30 мин до сна.
5. **Финальная валидация**: если идеальное расписание не проходит проверку, возвращается безопасный дефолт:
   - сон **23:00**, подъём **07:00**, работа **09:00–18:00**, отдых **19:00–21:00**.
