## 2. Изменённый план по итогам Раунда 1 (Версия 0.2)

**Изменения после обсуждения с Заказчиком:**
1. Задача сохранения разделена на три независимых требования: базовое сохранение в SQLite `FR-008` (6 ч), восстановление при старте `FR-009` (4 ч) и обработка ошибок БД `FR-010` (4 ч). За счёт выбора SQLite через QSQLITE (`ADR-0003`) трудоёмкость снижена с 16 до 14 ч, но работы распределены по итерациям.
2. Приоритет базового сохранения `FR-008` повышен с `20` до `10` (выпускается во 2-й итерации вместе со статусами), а `FR-009` и `FR-010` перенесены на приоритет `20`/`30` в 3-ю итерацию.
3. Требование об уведомлениях через системный трей (`FR-015`, `FR-016`) добавлено в объём с приоритетом `40`.
4. Оценка интеграции JKQTPlotter6 (`FR-012`) увеличена до 12 ч из-за сложности настройки трех независимых представлений.

## 5. Риски и допущения

| Риск | Влияние | Мера |
|---|---|---|
| Недоступность драйвера QSQLITE в целевом окружении | Блокирует `FR-008`..`FR-010` | Проверить в Итерации 1, зафиксировать в README |
| Отсутствие системного трея в среде проверки | Блокирует демонстрацию `FR-015` | Проверить `QSystemTrayIcon::isSystemTrayAvailable()`, реализовать деградацию (`NFR-011`) |
| Сложность JKQTPlotter6 для Junior | Задержка `FR-012` | Статистику ведёт Middle, Junior — тесты и настройки |
| Рост объёма данных | Замедление интерфейса | Ограничиться типичным объёмом, при росте — вынос чтения в поток (`ADR-0004`) |

**Допущения:** ставки и длительность итераций — учебные; бюджет приведён для сопоставимости с шаблоном и не является коммерческой оценкой.
